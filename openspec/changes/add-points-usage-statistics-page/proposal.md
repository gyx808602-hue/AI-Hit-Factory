## Why

当前项目已经具备工作台、任务记录、素材库等 SaaS 页面底座，但积分体系还缺少一个可访问的统计与使用记录入口。积分是 AI 生成任务计费、企业用量追踪和后续充值/退款链路的核心资产，需要先用 OpenSpec 固化页面范围、字段预留、接口边界和验收标准，再进入代码实现。

## What Changes

- 新增“积分统计”页面能力，展示积分余额/消耗概览、积分使用记录列表和记录详情入口。
- 页面布局参考用户提供图片的结构形式：左侧沿用现有应用壳，内容区采用上方统计卡片 + 下方记录列表；页面颜色、字体、圆角、卡片、按钮、表格和交互反馈全部采用当前项目现有风格，不新增独立视觉主题。
- 积分使用记录列表预留后端字段契约；当前接口尚未提供正式字段时，先定义前端 TypeScript 类型、API Client、React Query hooks 和 Mock 数据，避免页面直接散落临时字段。
- 操作列新增“详情”按钮，点击后展示积分记录详情弹窗或抽屉；详情字段先按业务语义预留，不强依赖真实接口已返回。
- 接入静态路由注册表和菜单元数据，后续可由动态菜单/权限码过滤展示。
- 本变更只创建 OpenSpec 文档和后续实现任务，不直接修改业务代码。

## Capabilities

### New Capabilities

- `points-usage-statistics-page`: 提供积分统计页、积分使用记录列表、记录详情入口、字段契约预留、路由菜单接入和基础交互状态。

### Modified Capabilities

- 无。

## Impact

- 前端页面：后续实现将新增积分统计页面、积分记录详情展示、筛选/分页/空态/加载态/错误态。
- 前端领域模块：后续实现将新增 `points` 相关类型定义、Mock 数据、API Client、React Query hooks 和页面级组件。
- 路由菜单：后续实现将新增积分统计页面的 route key、路径、菜单标题、图标和权限码预留。
- API 契约：当前真实接口字段未定，先预留前端契约，未来接入真实后端时只替换 API Client 数据源，不改页面调用方式。
- 后端/数据库：本次 OpenSpec 不要求后端改造，但设计会明确推荐字段和分页契约，便于后续联调。
