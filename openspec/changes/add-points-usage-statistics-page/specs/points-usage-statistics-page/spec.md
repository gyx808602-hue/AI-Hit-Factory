## ADDED Requirements

### Requirement: 积分统计页必须展示积分概览

系统 SHALL 提供积分统计页面，并在页面首屏展示积分账户摘要信息，包括当前可用积分、累计获得积分、累计消耗积分、最近更新时间和有效期提示。

#### Scenario: 用户访问积分统计页

- **WHEN** 已登录且具备积分查看权限的用户访问积分统计页
- **THEN** 系统 MUST 展示当前积分概览卡片，并显示可用积分、累计获得、累计消耗和最近更新时间

#### Scenario: 积分摘要加载失败

- **WHEN** 积分摘要接口或 Mock 数据源返回错误
- **THEN** 系统 MUST 展示可理解的错误状态，并提供重新加载入口

### Requirement: 积分统计页必须展示积分使用记录列表

系统 SHALL 在积分统计页展示积分使用记录列表，列表 MUST 至少预留记录 ID、流水号、业务类型、积分变动、变动方向、余额快照、关联业务、操作人、状态和发生时间字段。

#### Scenario: 使用记录正常展示

- **WHEN** 积分使用记录数据加载成功
- **THEN** 系统 MUST 以表格形式展示积分使用记录，并清晰区分收入、支出、退款和冻结等变动方向

#### Scenario: 使用记录为空

- **WHEN** 当前筛选条件下没有积分使用记录
- **THEN** 系统 MUST 展示空态，而不是展示空白页面或错误提示

### Requirement: 积分使用记录列表必须支持查询态预留

系统 SHALL 为积分使用记录列表预留服务端分页、筛选和排序查询形态，包括页码、页大小、关键词、业务类型、变动方向、状态和时间范围。

#### Scenario: 用户切换分页

- **WHEN** 用户切换积分使用记录分页
- **THEN** 系统 MUST 使用新的分页参数重新获取记录，并保持表格加载态可见

#### Scenario: 用户使用筛选条件

- **WHEN** 用户选择业务类型、变动方向、状态或时间范围筛选条件
- **THEN** 系统 MUST 使用筛选参数刷新记录列表，并将页码重置到第一页

### Requirement: 积分使用记录必须提供详情入口

系统 SHALL 在积分使用记录列表的操作列提供“详情”按钮，用于查看单条积分记录的完整信息。

#### Scenario: 用户点击详情按钮

- **WHEN** 用户点击某条积分使用记录的“详情”按钮
- **THEN** 系统 MUST 打开详情弹窗或抽屉，并展示该记录的流水信息、积分变动、关联业务、操作人、状态和备注

#### Scenario: 详情数据加载失败

- **WHEN** 用户打开详情但详情数据加载失败
- **THEN** 系统 MUST 在详情区域展示错误状态，并允许用户关闭详情视图

### Requirement: 积分页面必须遵循现有工作台视觉风格

系统 SHALL 复用当前应用壳和现有页面视觉风格，积分页面布局 MUST 参考用户提供图片的卡片式结构，但颜色、字体、圆角、卡片、按钮、表格和状态反馈 MUST 采用当前项目已有风格。

#### Scenario: 页面在桌面工作台中展示

- **WHEN** 用户在现有应用壳内访问积分统计页
- **THEN** 系统 MUST 保持侧边栏、顶部栏、页面背景、卡片描边、品牌强调色、按钮和表格样式与当前项目一致，不得出现明显割裂的页面风格

#### Scenario: 页面在窄桌面宽度展示

- **WHEN** 浏览器宽度处于 1024px 到 1279px 区间
- **THEN** 系统 MUST 保持概览卡片和记录表格可访问，表格可通过横向滚动或列宽控制避免关键操作被遮挡

### Requirement: 积分页面必须接入路由和权限预留

系统 SHALL 为积分统计页接入静态路由注册表，并预留菜单权限码和详情操作权限码，后续动态菜单只能通过 route key 映射前端组件。

#### Scenario: 路由注册成功

- **WHEN** 用户访问积分统计页对应路径
- **THEN** 系统 MUST 通过静态路由注册表渲染积分统计页组件

#### Scenario: 动态菜单返回积分 route key

- **WHEN** 后续后端菜单返回积分统计页 route key
- **THEN** 前端 MUST 基于静态注册表过滤并渲染对应菜单入口，而不是执行后端下发的任意组件路径
