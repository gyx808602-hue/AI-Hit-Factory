# AI Hit Factory 移动端开发项目描述

## 1. 项目定位

AI Hit Factory 是一个面向商家、运营人员和内容团队的 AI 内容生产 SaaS 平台。当前 Web 端以后台工作台形态运行，核心目标是帮助用户完成短视频内容生产相关流程，包括素材上传、AI 文案生成、图文生成视频、爆款视频改编、数字人训练、音色管理、数字人视频生成、任务进度查看和积分消耗统计。

移动端开发不建议直接照搬桌面端后台布局，而应围绕“快速创建任务、查看生成进度、预览成片、补充素材、处理失败任务”设计轻量化工作流。移动端的核心价值是让用户在手机上随时发起和跟踪 AI 生成任务，而不是完整复刻复杂表格型后台。

## 2. 当前前端技术栈

- 构建工具：Vite
- 前端框架：React 19 + TypeScript
- 路由：React Router
- 请求层：Axios 二次封装
- 服务端状态：TanStack React Query
- 全局状态：Redux Toolkit，当前主要承载 UI 偏好配置
- UI 组件：Ant Design 6
- 样式：Tailwind CSS 4 + CSS Variables
- 图标：lucide-react、Ant Design Icons
- 测试：Vitest + Testing Library

移动端如果继续使用 Web 技术，可优先选择 React 移动适配方案或独立移动 H5。若开发原生 App 或小程序，建议复用当前接口契约和业务状态模型，但重新设计移动端页面结构。

## 3. 业务模块概览

### 3.1 登录与账号

当前项目已有账号密码登录、短信登录预留、验证码、退出登录、刷新 token、首次登录强制改密、鉴权失效跳转登录等能力。

移动端需要保留：

- 登录页
- token 存储与自动携带
- refresh token 静默续期
- 登录失效后跳转登录
- 强制改密弹窗或独立页面
- 当前用户信息展示与退出登录

### 3.2 动态菜单与权限

Web 端通过 `/user-api/menus/routes` 获取当前用户可访问菜单，再映射到前端静态组件。这个设计的本质是“后端控制权限与菜单，前端只负责渲染已授权功能”。

移动端可以继续复用该权限模型，但不必完全复用 Web 侧边栏。建议移动端将菜单映射为：

- 首页快捷入口
- 底部 Tab
- 功能宫格
- 我的页面中的账号与权限入口

### 3.3 图文生成视频

现有能力：

- 支持纯文本、图片、图文混合输入模式
- 支持图片上传
- 支持根据主题和参考图生成提示词
- 支持创建视频生成任务
- 支持任务列表、详情、状态、进度、成片链接、失败原因

移动端建议页面：

- 图文生成视频创建页
- 图片上传与预览页
- 提示词编辑页
- 任务详情页
- 成片预览页

### 3.4 爆款视频改编

现有能力：

- 创建改编任务
- 上传参考视频、商品图、人物图、参考音频
- 填写商品信息、口播文案、内容方向
- AI 自动生成商品信息
- AI 自动生成口播文案
- AI 生成提示词
- 检查提示词
- 生成视频
- 查看任务进度、成片、封面、失败原因

移动端应把桌面端三步流程拆成更适合手机的向导式流程：

1. 创建任务
2. 上传素材
3. 补充商品与口播信息
4. 生成或编辑提示词
5. 提交生成视频
6. 查看进度与结果

### 3.5 数字人管理

现有能力：

- 数字人列表
- 状态筛选与搜索
- 创建数字人
- 上传图片或视频训练素材
- 查看详情
- 刷新训练状态
- 删除数字人

移动端建议强调卡片列表和详情页，弱化宽表格。创建数字人时重点处理素材上传、训练类型、语言、错误跳过等字段。

### 3.6 音色管理

现有能力：

- 音色列表
- 创建音色
- 音频地址或上传音频
- 文本与试听文案
- 状态、进度、失败原因
- 刷新与删除

移动端建议重点做好音频上传、试听、训练状态查看。音频预览控件应使用移动端原生或类原生体验。

### 3.7 数字人视频

现有能力：

- 数字人视频任务列表
- 创建数字人视频
- 支持文本驱动和音频驱动
- 支持选择数字人、音色、自定义音频
- 支持背景、尺寸、人物位置、语速、音调、音量、字幕、水印、分辨率等参数
- 支持任务详情、刷新、删除、视频预览

移动端建议先实现核心闭环：

- 选择数字人
- 选择驱动方式
- 输入文本或上传音频
- 选择基础画布比例
- 提交生成
- 查看任务进度与结果

复杂参数建议折叠到“高级设置”，避免首屏表单过重。

### 3.8 积分统计

现有能力：

- 可用积分、总获得、总消耗、冻结积分、即将过期积分
- 积分流水列表
- 业务类型、方向、状态、时间范围筛选
- 关联业务、操作人、工作空间、备注等信息

移动端建议：

- 首页或“我的”页面展示积分摘要
- 积分明细使用列表卡片
- 筛选项放入抽屉或弹层

## 4. 核心接口范围

移动端开发可优先对接以下接口模块：

- 登录认证：`/auth/login`、`/auth/login/sms`、`/auth/sms/code`、`/auth/refresh`、`/auth/logout`、`/auth/password`
- 当前用户菜单：`/user-api/menus/routes`
- 文件上传：`/uploads/audio`、`/uploads/image`、`/uploads/video`
- 图文生成视频：`/text-image-video/tasks`
- 爆款视频改编：`/video-remix-tasks`
- 数字人：`/digital-persons`
- 音色：`/customised-audios`
- 数字人视频：`/digital-person-videos`
- 积分统计：`/points/usage`

当前请求层统一将后端 `Result` 结构解包为 `data`，移动端如果不是复用 Web 请求层，也需要实现同样的响应处理、错误提示、token 续期和鉴权失败处理。

## 5. 移动端信息架构建议

建议移动端采用 4 个一级入口：

- 首页：快捷创建、最近任务、积分摘要、失败任务提醒
- 创作：图文生成视频、爆款改编、数字人视频
- 资产：数字人、音色、素材或历史成片
- 我的：账号信息、积分、权限、退出登录

任务类页面统一采用“列表 + 详情”的结构：

- 列表页展示任务名称、状态、进度、更新时间、失败原因摘要
- 详情页展示素材、配置、提示词、生成状态、成片预览、重试或刷新操作
- 创建页采用分步表单，避免一次展示大量字段

## 6. 移动端体验重点

- 上传体验：图片、视频、音频上传要有进度、失败重试、删除本地引用、上传成功预览。
- 任务状态：AI 生成是异步过程，移动端必须突出“处理中、成功、失败、可刷新”的状态反馈。
- 表单防重复提交：提交、生成、上传按钮必须有 loading 和 disabled。
- 错误提示：失败原因要展示给用户，接口错误使用统一 toast 或弹层。
- 成片预览：视频结果应支持移动端全屏播放、封面展示和外链打开。
- 权限控制：未授权功能不显示或显示无权限说明，不能只依赖前端隐藏。
- 复杂配置折叠：数字人视频的画布、字幕、水印、人物尺寸等字段建议归入高级设置。

## 7. 移动端开发边界

首版移动端建议先做“高频核心闭环”，不建议一次性复刻全部后台能力。

优先级建议：

1. 登录、鉴权、用户信息、退出登录
2. 首页与任务概览
3. 图文生成视频创建、任务列表、详情预览
4. 爆款视频改编任务列表、详情、基础创建流程
5. 数字人和音色列表、详情、状态刷新
6. 数字人视频基础创建流程
7. 积分摘要与积分流水
8. 高级参数、完整权限管理、系统管理类能力

## 8. 给移动端开发的简短描述

AI Hit Factory 移动端是一个面向商家和内容运营人员的 AI 短视频创作工作台。用户可以在手机上登录账号，上传图片、视频、音频等素材，创建图文生成视频、爆款视频改编、数字人视频等 AI 生成任务，并随时查看任务进度、失败原因和最终成片。系统同时提供数字人资产、音色资产、积分消耗记录和权限菜单能力。移动端首版应优先完成任务创建、任务跟踪、素材上传、视频预览和账号鉴权闭环，复杂后台管理能力可后置。
