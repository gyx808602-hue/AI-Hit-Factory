### 当前判断
- 当前这段 Vite `proxy` 配置本身没有明显语法问题。
- `rewrite` 规则已经生效，否则 Vite 不会报出 `/user/user-api/v1/auth/captcha` 这个重写后的路径。
- 现在的根因不是“前端代理没转发”，而是 `target` 指向的 `192.168.77.204:8000` 没有接受 TCP 连接。
- 从对照结果看，外网备选地址 `47.96.142.28:8000` 是活的，所以问题更像是：
  - 当前机器无法访问内网服务地址
  - 或后端服务未监听 `192.168.77.204:8000`
  - 或服务只绑定了 `127.0.0.1`
  - 或 Docker / 防火墙 / 安全组没有放通 8000 端口

### 后端原理点拨
- `ECONNREFUSED` 和 `404`、`401` 不一样。
- `404` 说明“服务收到了请求，但路径不对”。
- `401` 说明“服务收到了请求，但鉴权失败”。
- `ECONNREFUSED` 说明“TCP 连接阶段就被拒绝了”，请求根本还没进入后端应用层。
- 这就像前端里请求拦截器都还没跑到业务判断，请求在浏览器和服务器建立连接那一步就失败了。

2. 如果后端在容器里，检查端口映射是否正确，例如是否把容器内 `8000` 暴露到了宿主机 `8000`。
3. 如果你当前应走公网服务，可临时把 `target` 切到 `http://47.96.142.28:8000` 验证前端链路是否恢复。
